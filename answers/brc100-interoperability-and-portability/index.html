Is BRC-100 real interoperability or one vendor's interface?

“A document called a standard is not interoperability. Show independent wallets, conformance tests, and portable user data.”
Short answer

The answer without the theater.

BRC-100 is a published wallet-to-application interface covering actions, baskets, signatures, encryption, certificates, permissions, and discovery. It is not a token standard. A specification plus working implementations is meaningful, but genuine interoperability requires shared test vectors, independent implementations, compatibility reporting, and demonstrated migration.

What is true

The objection's strongest ground

  • The BRC corpus is public and accepts proposals and discussion through a public repository process.
  • Wallet Toolbox and related SDKs provide inspectable implementation surfaces.
  • An application using one implementation successfully does not prove vendor-neutral compatibility.
What remains unresolved

Do not claim more than the evidence

  • The current ecosystem does not yet present the kind of prominent, independently maintained conformance matrix that would settle this objection.
  • Wallet interface portability does not erase the settlement, governance, liquidity, or legal risks of the underlying rail.
Inspect it yourself

A better next move than arguing

  1. Run the same application request against more than one conforming wallet implementation.
  2. Inspect permission prompts, action history, key derivation, certificate handling, and data export—not just payment success.
  3. Ask for public conformance tests and failures, not only compatibility claims.
Falsifiability

What would change this answer?

Multiple independent implementations passing a public conformance suite would materially strengthen the claim. Interface drift or vendor-specific behavior without tests would weaken it.
