Is the Open BSV License actually open—and can builders exit?

“Critical BSV software is source-available but usable only on BSV. That is legal and technical lock-in.”
Short answer

The answer without the theater.

The Bitcoin SV node's Open BSV License allows broad dealing in the software subject to conditions, including BSV-only use for the software and derivatives. That differs materially from MIT or Apache-2.0. The current TypeScript stack contains packages with different license files, including MIT-licensed components and Open BSV-licensed ones. Builders should produce a bill of materials and test migration boundaries before relying on any package.

What is true

The objection's strongest ground

  • Open BSV License Version 5 conditions the node software and derivatives to use on BSV blockchains.
  • Source availability, OSI-approved open-source licensing, permissive reuse, and practical portability are different properties.
  • The current TypeScript monorepo contains multiple packages and license files; no site-wide label substitutes for checking each one.
What remains unresolved

Do not claim more than the evidence

  • This brief is not legal advice and does not decide whether a particular derivative work triggers a condition.
  • A public standard can be reimplemented in principle while still lacking a practical independent implementation or migration path.
Inspect it yourself

A better next move than arguing

  1. Generate a software bill of materials with exact versions, repositories, license files, and transitive dependencies.
  2. Ask counsel about every BSV-only component material to the product's contingency plan.
  3. Run a migration exercise: export user data, replace hosted services, and identify rail-bound transaction semantics.
Falsifiability

What would change this answer?

Permissive relicensing, independent implementations, and tested migration paths would reduce exit risk. More critical BSV-only dependencies or ambiguous package licensing would increase it.
